## Wi-Fi MCS Calculator 2.0.1

### Fixed: invalid MCS values in the selector

The MCS dropdown used to offer indices a standard does not define — 802.11b let you pick
MCS 0–13 even though only 0–3 exist, and 802.11a/g offered 0–13 instead of 0–7. The list
now comes straight from the rate table for the selected standard, bandwidth and guard
interval, so only values that actually resolve to a data rate are offered:

| Standard | MCS choices |
| --- | --- |
| 802.11b | 0–3 |
| 802.11a / 802.11g | 0–7 |
| 802.11n | 0–8 |
| 802.11ac | 0–8 at 20 MHz, 0–9 at 40/80/160 MHz |
| 802.11af / 802.11ah | 0–9 |
| 802.11ax | 0–11 |
| 802.11ad | 0–12 |
| 802.11be | 0–13 |
| 802.11bn | 0–13, 15, 17, 19, 20, 23 |

The selector also refreshes when the bandwidth changes, and it is correct on startup rather
than only after touching the standard dropdown. A still-valid selection is kept; otherwise
it falls back to MCS 0.

Calculated data rates themselves are unchanged — this only stops impossible choices from
being offered.

### Platforms

- Windows: 32-bit Intel/AMD, 64-bit Intel/AMD, ARM64
- Linux: x86_64, ARM64 (`.tar.gz`, so the executable bit survives)

Each artifact is built on a runner of its own architecture and its PE/ELF header is
verified during the build.
